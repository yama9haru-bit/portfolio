## 解決した課題

英語学習コンテンツとして需要のあるショート動画を、素材選定からテロップ焼き込みまで人手で行うと工数がかかる。一方でモデル任せの全自動生成は、権利判断や不適切コンテンツのチェックを飛ばしたまま公開してしまうリスクがある。工程の大部分は無人化しつつ、投稿の最終判断だけは必ず人間に残す設計が必要だった。

## 技術スタック

| 分野 | 技術 | 役割 |
|------|------|------|
| 動画取得 | yt-dlp | 既存動画のダウンロード |
| 文字起こし | faster-whisper | ローカル完全オフラインでの文字起こし(APIキー不要) |
| 動画処理 | ffmpeg (static-ffmpeg) | 区間切り出し・二言語テロップの焼き込み |
| clip-spec生成 | Python (deterministic_draft.py) + 差し替え可能なLLMフック | 決定的フォールバック付きのショート動画設計生成 |
| 安全ガード | Python (validate_clip_spec.py / safety_check.py) | 構造チェックと語彙ベースの安全ガード |
| 配信 | YouTube Data API (OAuth) | 非公開アップロードと人間承認後の公開 |
| 通知 | Discord (hermes send) | バッチ処理結果の一括通知 |

## 実装内容

英語の既存動画(映画予告・コメディ切抜き・トーク・スピーチ等)からバズる/学習価値のある区間を抜き出し、二言語・重要表現テロップを焼き込んだ縦型ショート動画を無人で生成するパイプラインを構築した。

- **決定的フォールバック**: clip-spec生成(LLM工程)はモデル呼び出し失敗時、`deterministic_draft.py`による機械的なドラフト生成に自動フォールバックし、モデルが使えない環境でも最後まで処理が完結する。
- **3層の安全設計**: `validate_clip_spec.py`による構造・編集ルーブリックの機械チェック、`safety_check.py`による語彙ベースの決定的コンテンツ安全ガード、人間による`final.mp4`の最終一括レビューの3層で危険な出力の公開を防ぐ。
- **human-in-the-loop**: 生成した動画はYouTubeへの非公開アップロードまでは自動化し、公開は`publish.sh`を人間が明示的に実行するまで行わない設計にした。
- **バッチ処理**: `run.sh`はキューに溜まった候補を全件処理し、成功/失敗をまとめた1通のDiscord通知で人間に報告する。修正が必要な出力は`fix.sh`で該当分のみ再生成できる。
- **0円運用**: yt-dlp/faster-whisper/ffmpegはいずれもOSSでAPIキー不要。LLMフックを使う場合のみそのモデルのコストが発生する構成にした。

## 成果・効果

- モデル未設定でも動作を止めない決定的フォールバック設計により、LLM依存を最小化しつつパイプラインを完結させた
- 構造チェック・安全ガード・人間レビューの3層により、権利判断や不適切コンテンツの公開を防ぐガードレールを構築した
- 投稿の最終承認を必ず人間に残すhuman-in-the-loop設計で、無人化と安全性を両立した
