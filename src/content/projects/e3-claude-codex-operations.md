## 解決した課題

複数のAI CLIツールを単独で使う場合、それぞれの強みを活かしきれない。Claude CodeとCodexという2つのAI CLIを並行運用し、それぞれの特性を補完的に活用する体制設計が必要だった。本質的な問いは「AIエージェントにどこまで自律性を与え、どこに人間のチェックポイントを置くか」であった。

## 技術スタック

| 分野 | 技術 | 役割 |
|------|------|------|
| AI CLI (主力) | Claude Code | オーケストレーターとしての自律開発 |
| AI CLI (2nd) | Codex | セカンドオピニオン・検証役 |
| 運用設計 | プロンプト設計 | 各CLIの役割定義とプロンプト最適化 |

## 実装内容

2つのAI CLIツール（Claude Code / Codex）を独立並行運用する体制を設計した。Claude Codeを主力オーケストレーター、Codexをセカンドオピニオンとして使い分ける基本構成を定義した。

3つの運用モデルを設計した。

**1. 自律×安全弁のモデル**: Claude Codeが自律的に開発を進め、Codexが安全弁としてレビュー・検証を行う。一方が生成し、もう一方が検証する棲み分け。

**2. スキル化×進化のモデル**: 各CLIのスキル（再利用可能なプロンプト・ワークフロー）を蓄積し、継続的に進化させる。スキルの共通化とCLI固有最適化のバランスを設計。

**3. 並行AIのモデル**: 同じタスクを両CLIに並行で実行させ、結果を比較・統合する。異なるアプローチの交叉から、より良い解を導出する。

本質的な問い「AIエージェントにどこまで自律性を与え、どこに人間のチェックポイントを置くか」に対して、各モデルごとの自律性の度合いとチェックポイントの配置を明示した。

## 成果・効果

- 2つのAI CLIの特性を補完的に活用する並行運用体制を設計
- 3つの運用モデルにより、タスクの性質に応じた使い分けを可能化
- 自律性と人間のチェックポイントのバランスを明示し、リスクを管理
- 開発効率を最大化するマルチCLI運用の指針を確立
