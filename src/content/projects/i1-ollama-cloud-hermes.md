## 解決した課題

Hermes Agentから最新のオープンソースAIモデルを利用するため、Ollama Cloud APIの統合設定が必要だった。ただし、Hermesのプロファイルごとの環境変数管理方式により、API keyの設定とフォールバック連鎖の設計で複数の技術的ハマりポイントが発生した。

## 技術スタック

| 分野 | 技術 | 役割 |
|------|------|------|
| エージェント基盤 | Hermes Agent | AIエージェントの実行基盤 |
| AI API | Ollama Cloud API | 35モデルへのクラウドアクセス |
| 設定管理 | YAML config | プロファイル・フォールバック連鎖の定義 |

## 実装内容

Ollama Cloud API keyを使ってHermesからGLM/Kimi/DeepSeek等の最新オープンモデルを利用可能にする設定を構築した。

**ハマったポイント**: プロファイルの`.env`が独立しており、メインの`.env`にAPI keyを設定してもプロファイルが継承しない問題が発生した。各プロファイルの`.env`ファイルに個別にAPI keyを設定する必要があることを切り分け、解決した。

**フォールバック連鎖の設計**: 35モデルを用途・コスト・性能に応じて階層化し、プライマリモデルが利用不可の場合に自動的に代替モデルにフォールバックする連鎖を設計した。

**35モデルの内訳**: GLM系4モデル、Kimi系3モデル、DeepSeek系4モデル、MiniMax系4モデル、Qwen系3モデル等、多様なタスクに対応可能なラインナップを構成した。

## 成果・効果

- 35モデルをHermesから利用可能にし、タスクに応じた最適モデル選択を実現
- プロファイル独立`.env`問題の切り分けと解決により、全プロファイルでAPI keyが正常に機能
- フォールバック連鎖の設計により、モデル障害時の可用性を確保
- コスト最適化されたエージェント基盤を構築
